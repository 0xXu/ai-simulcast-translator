# 多语言同声传译设计

## 1. 目标

将当前固定的英语转简体中文链路改为会话级多语言翻译：

- 源语言默认自动检测，也允许用户手动指定。
- 目标语言由用户从可搜索的常用语言列表中选择。
- 源语言与目标语言相同时直接显示原文，不调用 MiMo。
- 保留现有最近 5 句或 20 秒的上下文翻译与回溯修订能力。
- 英语转简体中文仍是默认配置，现有演示流程不变。

“支持任意语言”在 MVP 中定义为：不在业务协议中固定英语或中文，允许
faster-whisper 多语言模型支持的源语言与 MiMo 能正确理解的目标语言组合。
界面首版只列出常用语言，不承诺所有语言具有相同识别和翻译质量。

## 2. 产品行为

### 2.1 语言选择

控制窗口在开始按钮上方增加两个可搜索的选择框：

- 源语言：默认“自动检测”，并提供常用语言手动选项。
- 目标语言：默认“简体中文”，不提供“自动检测”。

首版常用语言：

| 代码 | 显示名称 |
| --- | --- |
| `zh` | 简体中文 |
| `en` | 英语 |
| `ja` | 日语 |
| `ko` | 韩语 |
| `fr` | 法语 |
| `de` | 德语 |
| `es` | 西班牙语 |
| `it` | 意大利语 |
| `pt` | 葡萄牙语 |
| `ru` | 俄语 |
| `ar` | 阿拉伯语 |
| `hi` | 印地语 |

源语言额外支持值 `auto`。语言值使用稳定的 ISO 639-1 风格代码，显示名称只
用于界面和 MiMo 提示词，不作为协议标识。

语言设置在会话启动后禁用，停止会话后恢复。首版不支持会话中切换语言。

### 2.2 自动检测

源语言为 `auto` 时，faster-whisper 不传入固定 `language`，由模型对识别窗口
执行语言检测。ASR 结果返回检测到的语言代码及检测概率。

为了避免短窗口造成语言抖动：

1. 会话第一次返回非空且语言概率不低于 `0.5` 的结果时，确定会话源语言。
2. 后续识别继续使用模型返回结果，但翻译路由使用已经确定的会话源语言。
3. 如果未达到阈值，源语言保持未知，MiMo 根据原文判断语言并翻译。

用户手动选择源语言时，Worker 将该语言代码传给 faster-whisper，不执行自动
语言路由。

### 2.3 同语种处理

当已知源语言与目标语言相同时：

- 不发送 MiMo 请求。
- `translatedText` 使用 ASR 原文。
- 保留现有重叠窗口去重、字幕时间线更新和锁定机制。
- 后续 Whisper 窗口修正原文时，同步修正可编辑区的展示文本。

自动检测尚未稳定前，不提前判定同语种，避免错误跳过翻译。

### 2.4 展示

控制窗口显示当前选择的“源语言 → 目标语言”。自动检测稳定后，将“自动检测”
更新为“自动检测（英语）”一类状态文本。

悬浮字幕保持双行结构：

- 主字幕显示目标语言文本。
- 次字幕显示源语言原文。

同语种模式下只显示一份主字幕，避免原文重复两次。

## 3. 架构设计

### 3.1 共享语言目录

在 contracts 包中建立唯一语言目录，包含：

```ts
type LanguageCode =
  | "zh"
  | "en"
  | "ja"
  | "ko"
  | "fr"
  | "de"
  | "es"
  | "it"
  | "pt"
  | "ru"
  | "ar"
  | "hi";

type SourceLanguageCode = LanguageCode | "auto";

interface TranslationSessionLanguages {
  sourceLanguage: SourceLanguageCode;
  targetLanguage: LanguageCode;
}
```

界面、IPC、主进程和翻译适配器均复用该目录，避免各层维护不同列表。

### 3.2 会话协议

`session.start`/ASR 启动请求增加 `languages`。主进程把源语言传给 Worker，并将
目标语言保存在当前字幕会话中。

ASR transcript 事件增加两个可选字段：

```ts
interface TranscriptLanguage {
  detectedLanguage?: LanguageCode;
  languageProbability?: number;
}
```

旧的 mock Worker 和测试夹具可不返回这两个字段，以保持协议向后兼容。

### 3.3 Whisper Worker

默认模型从仅英文的 `small.en` 改为多语言 `small`。Worker 启动参数增加
`--language`：

- `auto` 转换为 Python 配置中的 `None`。
- 具体语言代码原样传入 faster-whisper。

识别结果从 faster-whisper 的 `info.language` 和
`info.language_probability` 提取语言信息并写入 Worker JSON 协议。

环境变量 `WHISPER_MODEL` 仍可覆盖默认模型。若用户配置 `.en` 模型并选择非英语
或自动检测，启动时返回明确配置错误，避免静默产生错误字幕。

### 3.4 翻译协调

`SubtitleTranslationRequest` 增加：

```ts
sourceLanguage: LanguageCode | "unknown";
targetLanguage: LanguageCode;
```

MiMo system prompt 动态描述源语言与目标语言，不再出现固定的“英文窗口”或
“简体中文字幕”。模型仍必须返回现有严格 JSON 快照，并且只能修订未锁定字幕。

同语种直出通过独立 `SameLanguageTranslator` 实现 `TranslatorPort`，而不是在
React 或 MiMo Client 内添加分支。会话协调器根据稳定源语言选择 MiMo 或同语种
适配器，从而保留现有乱序响应保护和修订窗口规则。

源语言未知时继续调用 MiMo，并在提示词中声明“自动判断输入语言”。

### 3.5 状态管理

每个会话保存以下不可变配置：

- 用户选择的源语言。
- 目标语言。
- 自动检测后稳定的源语言，可为空。

停止会话时清空检测状态。新会话不得继承上一个会话检测到的语言。

## 4. 错误处理

- 目标语言为空或不在语言目录中：IPC 边界拒绝启动。
- 源语言代码非法：IPC 边界拒绝启动。
- `.en` Whisper 模型与非英语源语言冲突：Worker 启动失败并提示改用多语言模型。
- 自动检测概率不足：保持未知并继续翻译，不阻塞字幕。
- MiMo 不支持某个组合或返回错误：沿用当前失败状态和原文降级策略。
- MiMo 返回与目标语言不符：首版不增加二次语言检测，依靠提示词和现有一次格式
  重试；日志记录源语言与目标语言便于定位。

## 5. 测试策略

### 5.1 Python

- `auto` 不向 faster-whisper 固定语言。
- 手动语言正确传入模型。
- 结果协议包含检测语言和概率。
- `.en` 模型拒绝非英语与自动检测配置。

### 5.2 TypeScript

- contracts 验证合法与非法语言设置。
- Worker Adapter 正确传递 `--language`。
- ASR Controller 发布检测语言。
- MiMo Prompt 根据目标语言生成，不再固定中文。
- 未知源语言提示 MiMo 自动判断。
- 同语种适配器不发网络请求并返回原文。
- 新会话重置自动检测状态。

### 5.3 Renderer

- 默认显示“自动检测 → 简体中文”。
- 可搜索并选择常用源语言和目标语言。
- 采集中禁用选择框，停止后恢复。
- 自动检测结果更新状态标签。
- 同语种字幕不重复显示原文。

### 5.4 验收场景

至少完成以下真实音频验收：

1. 英语自动检测转简体中文。
2. 日语自动检测转英语。
3. 手动指定英语转日语。
4. 自动检测英语且目标为英语，确认不调用 MiMo。
5. 后文改变前文语义时，目标语言字幕仍在原位置回溯修订。

## 6. MVP 边界

本次不实现：

- 会话中动态切换语言。
- 一句话内多语言混说的独立分段。
- 下载并管理多个 Whisper 模型。
- 用户自定义任意语言代码或目标语言文本。
- 对 MiMo 输出执行额外语言识别。
- 保存语言偏好到云端。

本设计优先复用现有字幕时间线、翻译协调器和 IPC 架构，仅把语言从硬编码常量提升
为会话配置，避免为了多语言重写核心链路。
